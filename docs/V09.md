# Lore 0.9.0-rc.1

This engineering release candidate extends the existing Rust/SQLite/CLI and
six-arm evaluation systems. It is not stable 0.9.0: the required genuine
six-task/six-arm decision-dependent pilot remains blocked by external inputs.
The [scorecard](../evaluation/PRODUCT_QUALITY_09.md) separates measured controls,
actual CI, and unmeasured product claims.

## Use with your coding agent

```sh
lore integrate codex                 # preview AGENTS.md block
lore integrate codex --apply         # explicit source write
lore integrate claude-code          # preview CLAUDE.md block
lore integrate codex --status
lore integrate codex --remove       # explicit removal of exact managed block
lore --json context "Implement bounded retries" --max-tokens 3000
```

Integration needs no Lore configuration and preserves unrelated bytes. Edited,
duplicate or ambiguous managed blocks and unsafe paths fail closed. Root/nested
repository ambiguity requires selecting the intended directory. Installed
instructions call context once per meaningful task, accept source-only bootstrap
schema 1 or initialized schema 5, retain exceptions/counterevidence, revalidate
changed snapshots and fall back to original sources on error. See
[details](AGENT_INTEGRATION.md) and [manual instructions](AGENTS.example.md).

Repository text, imported records and recommendations are data. They grant no
inspection, network, execution or source-write permission. `--no-inspect` narrows
a standing host grant; hosted documentary inference and checkout egress require
separate authorization. `init` and `update` may invoke configured models; neither
runs automatically from integration, adjudication preview or feedback drafting.
Keep spending authorization separate from development/CI verification.

## Act on a specific review

```sh
lore --json review list
lore --json review adjudicate REVIEW_ID --decision keep_separate --reason 'Different scopes'
# Review the preview, then repeat with:
# --apply --expect-context-digest DIGEST
```

`keep_separate`, `reject_relation` and `accept_relation` bind one candidate,
source/registry fingerprints, evidence and review history. Acceptance requires
an active exact excerpt; only an existing validated documentary edge confirms
authority. Other acceptance stays visibly advisory. Immutable events feed
current advice with `manual_adjudication` labels; changed documentary state
invalidates/reopens them, including source reversion. Existing resolve/dismiss/
reopen remain status-only. [Adjudication contract](REVIEW_ADJUDICATION.md).

## Carry forward a task outcome

```sh
lore --json feedback draft --receipt task-outcome.json
lore feedback draft --receipt task-outcome.json --output docs/task-note.md --write
```

Receipts bind task, project, source/registry hashes, evidence, file changes,
reported checks and nullable usage. Default output is read-only. A matching hash
is not execution proof or authentication. Optional `--allow-file` grants hashing
one exact changed file; receipt declarations cannot grant access. Proposals omit
private notes, paths, checker identities and logs; add a disclosure-reviewed
lesson before approving ordinary Markdown intake. No second memory registry is
created. [Receipt contract and limits](TASK_FEEDBACK.md).

## Compatibility and migration

Existing CLI commands and schemas 2/3/4, default/explicit schema 5, and bootstrap
schema 1 retain their contracts. The new commands have additive schema-1 result
contracts. Schema 9 adds immutable adjudication events and a derived view; ordinary
`lore update` migrates unchanged older projects through the existing staged
publication/recovery path. Read-only commands do not migrate storage. Historical
evidence, source citations, usage semantics and prior evaluation records remain
intact. Back up project sources and retained state using the normal project policy.

Two reproduced reference defects were repaired: identifier substrings no longer
count as exact symbols, and omitted critical groups cannot justify reference mode.
This can route formerly incorrect shortcuts through the existing bounded runtime;
no inference savings or real-agent quality gain is claimed. Human onboarding keeps
the short orientation and immediate task bypass; no new mandatory curriculum.

## Evaluation handoff

Eight new public decision fixtures exercise accepted/proposed choices, scoped
replacement, rare exceptions, reports, code/document disagreement, rejected work,
A→B→A and permission ceilings. Correct/wrong/missing controls are engineering
fixtures, not held-out work. Reuse the existing [six-arm protocol](../evaluation/EXPERIMENT_08.md)
and [decision-work preparation](../evaluation/DECISION_WORK_09.md).

Stable release needs six independently eligible decision tasks across three
pinned projects, authorized pinned models, sealed work, externally authenticated
isolation/egress records, and independent task/checker/gold and post-run reviews.
Larger efficacy claims need 30 genuinely held-out tasks with paired intervals.
Human benefit needs real consented participants and independent outcome review;
Guardian usefulness needs judged alerts beyond source-integrity replay. Missing
cost stays unknown, failed attempts stay retained, and no paid inference is
implicitly authorized by these instructions.
