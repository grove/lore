# Inference and knowledge foundations

**Status:** Initial implementation contracts, not a functional CLI. See [DESIGN.md](../DESIGN.md) for architecture and product intent.

Lore's Rust foundation separates two forms of work. **Inference** interprets and reconciles project material, and **deterministic Rust and SQLite logic** controls source identity, evidence immutability, schema integrity, and publication state. The database must never trust an LLM to create a valid provenance link without checking the referenced source and excerpt. Likewise, an assertion that an issue is closed or that a deployment reportedly happened is not independent implementation verification.

The first code introduces object-safe asynchronous `GenerativeModel` and `DecisionModel` traits in [src/inference.rs](../src/inference.rs). A generative request contains instructions, input context, and an optional output JSON schema. A decision request contains named predicate, choice, and ordered-score questions. Responses are normalized into named, typed outcomes, with refusals preserved as refusals and probabilities checked for boundedness, valid options, proper distributions, and consistency with weighted scores. These types are designed for independent provider implementations, not an agent framework.

The offline wire adapters in [src/provider_wire.rs](../src/provider_wire.rs) translate Lore's canonical contracts to OpenAI Decisions (`/v1/decisions`, an array of named `predicate` / `choice` / `score` questions), Ollama or future TypeSafe System One (`/v1/systemone`, a map of named `noul` / `choice` / `score` questions), OpenAI Responses (`/v1/responses`, schema output via `text.format`), and Ollama Chat (`/api/chat`, optional `format`). The System One and OpenAI decision adapters do not share an HTTP wire protocol, even when the semantics of the questions are equivalent. There are no network clients, credential handling, provider capability checks, or live model calls in the current library. TypeSafe Jev is a future decision-provider candidate, not a required initial adapter.

The first [SQLite migration](../migrations/0001_knowledge.sql) gives source roots and files stable identifiers independent of their paths, records observed source and section revisions, and preserves exact original excerpts in append-only evidence snapshots. Per-source assertions have separate revision histories; consolidated knowledge units have their own revisions, documentary support relationships, cross-knowledge links, topics, and review records. SQLite enforces many referential constraints and protects historical snapshots and revisions from normal UPDATE or DELETE calls. Supersession requires an evidence reference in the schema, but deciding whether that evidence explicitly supports replacement is a semantic validation task for a future reconciler.

**Scope and limitations.** These are foundational storage and interface contracts, not the entire knowledge compiler. The Rust model clients, Markdown scanner, deterministic excerpt-hash verification, cross-section/source identity checks, temporal and supersession-cycle validation, transactionally recoverable publisher, privacy purge mechanism, and CLI commands still need implementation. The SQLite database may contain sensitive copied project text and must not be committed as a routine project artifact. Historical snapshots are preserved after source deletion until a separate, explicit privacy-oriented purge is implemented.

Run `cargo test --all-targets` to exercise [provider contract tests](../tests/provider_contracts.rs) and [SQLite schema tests](../tests/schema_contracts.rs). The tests are offline and need no Ollama installation or hosted API credentials. They check protocol mapping, refusal behavior, probability and option validation, local-only egress preflight, immutable evidence, source-revision foreign keys, and migration correctness. Later provider integration tests must validate these contracts against real API responses before Lore can claim production compatibility. Relevant external specifications: [OpenAI Decisions](https://developers.openai.com/api/docs/guides/decisions), [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [Ollama Clef-Flash](https://ollama.com/library/clef-flash), and [TypeSafe System One](https://docs.typesafe.ai/api).
