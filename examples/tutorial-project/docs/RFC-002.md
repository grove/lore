# RFC-002 — Consider five charge attempts

**Status: Proposed.** **Scope: Future production charge handling.**

The team is considering raising `MAX_CHARGE_ATTEMPTS` from three to five to improve recovery from transient gateway failures.

This RFC has **not been accepted**. It does not supersede ADR-001, authorize a production change, or prove the deployed implementation has changed.

Before any approval, measure duplicate-risk behavior, confirm the gateway's idempotency handling and explicitly decide whether the production rule should change.

**Open question:** Would additional attempts materially improve completion rates without increasing ambiguous outcomes?
