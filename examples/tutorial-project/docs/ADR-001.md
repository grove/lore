# ADR-001 — Charge submission retries

**Status: Accepted.** **Scope: Production charge submission.**

The production charge adapter must permit **no more than three submission attempts**, including the first attempt. The code constant representing this accepted limit is `MAX_CHARGE_ATTEMPTS = 3`.

Every retry of the **same logical charge** must reuse the **same idempotency key**. A retry must not create a new logical charge. A different key could lead to a duplicate payment.

Only transient, retryable errors qualify. When the outcome is ambiguous, the client must first request a read-only status check and must not submit again until an authorized decision establishes that a retry is safe.

This decision does **not** define a general retry count for refunds or for every provider.

**Why:** The team chose a bounded approach to avoid unintentional duplicate charges and unbounded retry storms. A later suggestion to increase the count is not an accepted replacement without an explicit scoped decision.
