# Atlas findings and validation plan

**Status: source-backed findings from the user-supplied 2026-10-08 evaluation, not a passing quality benchmark.** No user-provided raw model responses, wiki output, local state database, or credentials are committed here.

## What the first real run established

One complete Atlas benchmark used OpenAI-style hosted generative inference with the configured `gpt-6-luna` model and Ollama's `clef-flash` decision backend. The initial compilation processed nine sources in about 225 seconds, producing 35 source assertions and 35 knowledge units. The subsequent mutation added two Markdown documents and completed in about 83 seconds, bringing the knowledge-unit count to 40. Across both phases, the benchmark recorded 73 generative calls and 18 advisory decision calls. The unchanged follow-up run performed no inference and left generated Markdown unchanged. After the mutation, all 40 current source-excerpt checks passed. The SQLite referential-integrity checks also passed.

The original *strict, lexical gold-label proxy* matched kinds and lifecycles for 6 of 11 source checkpoints after mutation. Two of three original relationship expectations passed. These figures are not truthfulness or semantic-recall scores. The originally expected MySQL **equivalence** was itself an unsuitable gold rule: a January review that reaffirms an earlier accepted decision is a distinct documented event, not necessarily the same decision object. The benchmark now expects a source-grounded `reaffirms` relationship and keeps strict type labels alongside explicitly documented acceptable alternatives. **The updated benchmark must not be reported as improved model quality without a fresh real inference run.**

## Primary observed defect: chronology across topic pages

In the submitted generated wiki, one topic correctly identifies the later ADR that superseded the MySQL selection, while another describes an earlier MySQL reaffirmation as a conflict with the superseded state and implies the replacement was not identified. Both statements concern the same project decision history and must be consistent across topics. The wiki also treats one ADR's date as though it were necessarily the effective date of a deployment or state change. A date of publication, a decision event, and a reported production deployment are separate concepts.

The fix tracks explicitly supported decision relationships across topic boundaries, adds those relationships to the affected pages' synthesis and verification contexts, and displays a deterministic source-backed relationship section. The old topic is invalidated when a new cross-topic successor appears. This still cannot guarantee that any selected generative model will never make a temporal error; semantic review and a representative live-model rerun remain required.

## How to evaluate a meaningful improvement

Run the pinned Atlas benchmark again using the same exact source documents, declared provider settings, and supported model identifiers. Preserve the Lore binary SHA-256 and corpus file digests, and record the provider's resolved model identities where available. Review the actual pages, especially the pages containing original decision, reaffirmation, successor ADR, and reported deployment. Check that source evidence remains valid, no fabricated quote appears, none of the source events is silently erased, the reaffirmation is not forced to equal the original decision, and the initial MySQL selection is never described as the current accepted choice after explicit supersession.

Use `python3 evaluation/compare_runs.py <run-a> <run-b>` to compare separately generated runs. It reports lexical topic/statement overlap only when the original Markdown bytes match and flags differing or unknown build/provider identities. A high overlap does not prove correctness, and low overlap in intentionally different mutation phases is **not** a reproducibility failure. For more informative stability measurement, obtain at least three fresh runs of the identical initial Atlas corpus and exactly one pinned inference configuration, each with an empty cache. Have a human reviewer complete the seven criteria in each generated `REVIEW.md`; that is the source of semantic usefulness judgments.

The original evaluation did not record billed USD or input/output tokens. Never derive charges from call counts, and do not claim a speedup until similarly configured new runs establish one. More efficient candidate ranking and token/cost instrumentation remain separate follow-up work.

## Release gates before calling this beta validated

The required gates are no-op updates with zero calls and no changed output, preserved historical snapshots after source deletion, no ungrounded supersession, and consistent cross-topic decision history after an explicit ADR replacement. Each relevant page must accurately qualify the observed decision event versus reported deployment; an issue being closed is not implementation verification. Real-provider tests must exercise the chosen OpenAI/Ollama paths with actual credentials and model weights, and a human must assess semantic correctness. Target scores should be stated before scoring new runs, not retrofitted to the output.


## Follow-up: first post-fix live benchmark

A later complete Atlas run using commit `1d8b048`, Foundry `gpt-6-luna` as the generative model, and Ollama `clef-flash` for decisions completed initialization and the mutation phase, with a true no-op. It recorded 84 generative calls and 18 decision calls. The final SQLite state contained 43 knowledge units and 41 `elaborates` relationships, but **zero `reaffirms` and zero `supersedes` relationships**, despite the correct assertions being extracted and all live evidence quotes resolving.

Inspection of the preserved reconciliation log established two root causes. The January review explicitly reaffirmed the earlier MySQL decision, yet the LLM classified that relation as `elaborates`. When ADR-027 was introduced, the LLM **did** propose `supersedes` for ADR-001. Lore rejected it because the earlier source's extracted scope read `New ledger persistence work until another accepted ADR explicitly replaces ADR-001`, while ADR-027 used `production payments ledger`. The predecessor was identified by name in an exact source quotation. Comparing these two model-generated scope strings literally was therefore the wrong gate for this explicit document replacement.

The next fix adds deterministic, source-ID-anchored relation recognition to supplement the model: it corrects mistaken `elaborates` classifications when an exact quoted reaffirmation names a unique predecessor, accepts an explicitly named supersession despite paraphrased scope differences, and defers ambiguous or negated references for review. No improvement in live-model quality is claimed from the deterministic tests alone. The updated code still needs a fresh Atlas run at its new commit, with real inference, to establish whether the two missing relationships and cross-topic historical synthesis are now repaired. Raw local evaluation databases remain outside Git.

## Atlas live run at revision 6978a62: accepted status split and hidden degradation

The complete user-supplied live Atlas run took approximately 8m17s, with 35/35 valid post-mutation excerpt checks and an unchanged update using zero inference calls. Its initial overview used a marked source-excerpt fallback; its post-mutation overview was verified, but the ledger topic remained degraded. Relationship checks were 2/3 after mutation, because no active supersession of ADR-001 was stored. The post-mutation no-op response incorrectly omitted the published ledger's degraded_topics state. This is not a passing knowledge-quality evaluation.

The database explains the missing relationship. The generative model extracted an accepted assertion from ADR-027's metadata header without the replacement details, then separately extracted the substantive Decision statement that explicitly says PostgreSQL supersedes MySQL/ADR-001 with lifecycle unknown. The reconciliation model actually proposed supersession of ADR-001, but Rust correctly required an accepted successor decision and rejected the unknown one. The defect was that document-level acceptance had not been carried into its own Decision section. The new narrow parser derives acceptance only from a numbered ADR's explicit, unambiguous Status: Accepted before the subsections; it normalizes unknown lifecycle only for the same document's Decision section. Changes to that status invalidate the section digest. No deployment is independently verified by this inference.

The second fix reads source-excerpt degradation markers from the published Markdown when reporting unchanged updates, instead of relying on an empty transient runner status. The benchmark additionally compares initial and no-op quality reports. Both changes are covered by deterministic regressions and still require a fresh Foundry/Ollama run to establish improved live-model outcomes.

## Live Atlas rerun at revision 13dbc73 (before configurable reasoning)

A subsequent complete Atlas benchmark included in the user-provided evaluation archive finished in approximately 7m43s, including initial and mutated phases, using Foundry GPT-6 Luna and Ollama Clef-Flash. It recorded 39 valid current source excerpt checks after mutation, a verified project overview in both phases, an active supersession of ADR-001 by ADR-027, and a zero-inference-call, byte-identical post-mutation no-op that retained accurate degraded-topic reporting. The ledger topic still required evidence-only fallback, and relationship checks remained **2/3**, with the only missed positive link being the January reaffirmation. Human review remained unscored.

The retained SQLite source assertion identifies the review as a `decision` with lifecycle `active`: “The review reaffirmed that the production payments ledger remains committed to the MySQL decision in ADR-001.” The reconciliation log **explicitly proposed `reaffirms`** between the review and the already accepted ADR-001 decision. Nevertheless, Lore recorded no reaffirmation because its Rust validator and deterministic reference pass both required the *new reaffirmation event* to be classified `accepted`. The veto arose from conflating continuation of an earlier accepted decision with acceptance of a fresh decision. This is a domain-independent lifecycle error, not a failed source excerpt or wrong model relation.

The new implementation permits a positive, source-grounded reaffirmation recorded as an `active` or `accepted` decision event, but only when the source assertion's **own statement** describes the reaffirmation, the predecessor is an identifiable accepted decision, and negative/conditional and ambiguous language is excluded. Supersession still requires an accepted successor. The tests cover both software ADRs and organizational policies. The still-degraded ledger page is a **separate synthesis quality failure** (unsupported chronology and cross-topic claims in model prose), not a reason to weaken evidence validation. The 13dbc73 evaluation predates the reasoning-effort configuration merged at c87d360 and therefore cannot be used to infer its effectiveness. A fresh real-model run remains necessary.

## Follow-up: evidence identity and exact Markdown quote boundaries (post-PR #18)

A later real-inference run at `a9434a6` with unchanged model roles, reasoning settings, and a 64,000-byte context limit produced valid source evidence and a passing no-op, but neither the active reaffirmation nor accepted replacement edge was stored. The generated overview fell back to attributed excerpts after rejecting repeated drafts. The source-level scorer correctly reported missing edges; **this was not an evaluator failure**.

The retained state showed two independent sources of reconciliation failure. The extractor had created a standalone accepted-decision unit describing the predecessor document's `Status: Accepted` header alongside its substantive accepted decision. That metadata unit created an artificial ambiguous predecessor and vetoed otherwise source-grounded links. Separately, a model-suggested replacement passage included the original Markdown `## Decision` heading, while its extracted assertion quote contained only the section body. Both passages were exact, but the old validator required the *larger* relationship passage to be contained within the *smaller* assertion passage and rejected it.

The correction excludes **standalone accepted-status metadata** from automatic predecessor selection while preserving the observation and keeping truly multiple substantive decisions ambiguous. It admits source-backed nested quotations in either direction only when the actual extracted assertion quote also contains the positive decision action toward the unique predecessor. Tests use an organizational approval policy with a duplicate status-header unit, an explicitly reaffirming committee review, a heading-prefixed replacement quote, and a deliberately ambiguous multi-decision document. A separate rollout-plan test checks that source-relative uncertainty does not become a timeless current-state claim in the overview. These are generic contracts, not hardcoded Atlas identifiers or fabricated graph edges.

This new pipeline version requires a fresh real-inference run and human review. Previous runs and previous scorer versions remain historical results; neither deterministic tests nor re-scoring the old state establishes improved synthesis quality.
