# ADR-001: Production ledger database

Date: 2025-11-03
Status: Accepted
Scope: production payments ledger

## Context

The payments platform requires transactional durability, predictable query plans and a straightforward operational model. The team has more experience maintaining MySQL than operating a new database engine. This decision concerns the ledger service, not the analytics warehouse or development laptops.

## Decision

We selected MySQL as the primary database for the production payments ledger. PostgreSQL was discussed as an alternative, but it was not selected in this decision. The choice governs new ledger persistence work until another accepted ADR explicitly replaces ADR-001.

## Consequences

Schema changes must use versioned migrations and backward-compatible deployment steps. The team will reconsider the database only if new requirements justify the migration cost.
